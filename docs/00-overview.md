# 00 · Огляд, цілі, скоуп

## 1. Контекст

Існує опис нативного мобільного застосунку **SOFTSWISS MIX WEEK App** і
високодеталізований HTML-прототип його екранів (`design/`).

Поточне завдання — **не нативний застосунок**, а:

- **мобільна веб-версія** (PWA, mobile-first) — основний сценарій;
- **повноцінна десктопна адаптація** тих самих сценаріїв;
- **white-label**: одна платформа обслуговує кілька компаній, кожна зі своїм
  брендингом, який визначається автоматично за корпоративним доменом
  користувача і керується з адмін-панелі;
- **історія івентів**: перегляд минулих і майбутніх подій + реєстрація на
  майбутні;
- **фото після івенту**: посилання на зовнішні галереї (завантаження
  учасниками + галереї професійних фотографів), кожне з власною обкладинкою.

Прототип у `design/` — це **референс візуальної мови й копірайту**,
а не код для копіювання. Токени дизайн-системи з нього переносяться в
CSS-змінні і стають **дефолтним брендом платформи** (див. `docs/04`, `docs/05`).

## 2. Продуктова мета

Учасник корпоративного івенту в будь-який момент має отримати відповідь на
чотири питання за ≤ 2 тапи:

1. **Що зараз відбувається?**
2. **Що далі?**
3. **Де це?**
4. **Чи потрібна від мене дія?** (зареєструватись, прийти, забрати мерч,
   дотримати дрес-код)

Організатор має змінювати будь-який контент без релізу коду.

## 3. Цільові користувачі й ролі

| Роль | Хто | Де працює |
|---|---|---|
| `PARTICIPANT` | співробітник компанії-тенанта | застосунок учасника |
| `GUEST` | зовнішній гість за інвайтом | застосунок учасника, обмежений |
| `SUPPORT` | HR / чергова підтримка | адмінка: read-only (щоб швидко відповісти учаснику, нічого не змінивши) |
| `CONTENT_EDITOR` | контент-менеджер | адмінка: програма, мапа, медіа, переклади |
| `EVENT_MANAGER` | організатор івенту | усе вище + реєстрації, пуші, мерч |
| `TENANT_ADMIN` | адмін компанії | усе в межах свого тенанта + бренд, користувачі |
| `SUPER_ADMIN` | адмін платформи | усі тенанти, фіче-флаги, секрети, аудит |

Детальна матриця прав — `docs/10-admin.md`.

## 4. Скоуп v1 (MVP)

**Учасник:**
- Логін за корпоративною поштою (magic link + другий фактор), онбординг,
  прийняття Terms/Privacy.
- Список івентів: `Майбутні` / `Минулі` / `Мої`.
- Реєстрація на майбутній івент (з формою, capacity, waitlist).
- Сторінка івенту: Home (Зараз/Далі/Оголошення), Програма з фільтрами,
  «Моя програма», Мапа, EventStyle, Travel, Help, WinStyle.
- Реєстрація на окремі активності з обмеженою місткістю + waitlist.
- Медіа минулого івенту: картки-посилання на галереї з обкладинками
  + скарга на галерею.
- Історія сповіщень (in-app) з лічильником непрочитаних.
- Профіль: дані співробітника, мова, нотифікації, активні сесії, 2FA,
  контакти, вихід, експорт і видалення даних.
- PWA: інсталяція, офлайн-кеш програми/мапи/help, web push.

**Організатор (адмінка):**
- CRUD івентів, програми, мапи, EventStyle, Travel, Help, мерчу, медіа-лінків.
- Керування реєстраціями (підтвердження, чек-ін, експорт).
- Пуш/email-розсилки з сегментацією.
- Бренд-редактор (лого, палітра, шрифти, назва) з live-прев'ю.
- Фіче-флаги на тенант/івент.
- CSV-імпорт співробітників, HR-призначення.
- Переклади (en/ru/uk) з UI.
- Аналітика («Insights»): воронка реєстрації, топ-активності, PWA, медіа.
- Черга скарг на медіа.
- Аудит-лог, керування секретами інтеграцій.

**Платформа:**
- Мультитенантність з ізоляцією даних.
- Резолв бренду за доменом пошти.
- Безпека рівня OWASP ASVS L2 (`docs/12`).

## 5. Поза скоупом v1

Платежі/доставка/повернення мерчу · реальні платіжні дані · indoor-навігація

## 6. Ключові рішення й обґрунтування

| Рішення | Чому |
|---|---|
| PWA замість нативу | один кодбейз, миттєві оновлення, немає модерації сторів, вхід за посиланням |
| Моноліт Next.js | 3 000 користувачів не виправдовують розподілену архітектуру |
| Тенант визначається за доменом email | нульове тертя: користувач нічого не обирає, бренд «впізнає» його ще до логіну |
| Тема через CSS-змінні, не через збірку | зміна бренду в адмінці застосовується без деплою |
| Тільки посилання на фото | нуль ризиків GDPR-зберігання, нуль інфраструктури, нуль питань з правами фотографів |
| Секрети в БД під envelope encryption | ротація без деплою, аудит доступу, `.env` лише для bootstrap |
| Database sessions | миттєвий revoke сесій — критично для безпеки |

## 6a. Точки узгодження із замовником

Два рішення свідомо відхиляються від початкового формулювання. Їх треба
підтвердити **до старту Фази 0** — переробка пізніше дорога.

| # | Було у вихідному описі | Що в ТЗ | Чому | Що робити, якщо не погоджено |
|---|---|---|---|---|
| 1 | «Сторедж, куди люди заливають фото» | **тільки зовнішні посилання** з обов'язковою обкладинкою (`docs/08`) | зберігання чужих фото = GDPR-ризик, права фотографів, терабайти й модерація — усе це заради функції, яку вже виконують Drive/Pixieset | увімкнути фіче-флаг `media.self_hosted_upload` — схема під нього закладена, +6 днів (`docs/15`, беклог №5) |
| 2 | «Corporate authentication via SSO/AD» | **magic link + TOTP**, SSO/AD — поза скоупом v1 (`docs/03`) | інтеграція з корпоративним AD потребує ресурсу IT-відділу кожного тенанта; magic link працює для будь-якої компанії з першого дня, а провайдерний шар дозволяє додати SSO без переробки | Google OIDC — +1 день, SAML/AD — +4 дні, обидва без міграції даних |

Решта вимог реалізується як заявлено.

## 7. Глосарій

| Термін | Значення |
|---|---|
| **Tenant** | компанія-клієнт платформи (SOFTSWISS, Company2…). Межа ізоляції даних. |
| **Brand** | набір візуальних налаштувань тенанта або конкретного івенту (лого, палітра, шрифти, назва). |
| **Event** | подія-парасолька («Mix Week 2026», 21–27.10). Має дати, локацію, таймзону, реєстрацію. |
| **Activity** | пункт програми всередині івенту (воркшоп, турнір, вечірка, Gala Night). |
| **Track** | категорія активності: Workshop / Sport / Party / Team / Logistics. |
| **Venue / Place** | точка на мапі: сцена, готель, Care Zone, WinStyle-корнер, трансферний пункт. |
| **Registration** | реєстрація користувача на Event. |
| **Booking** | запис користувача на Activity (з місткістю та waitlist). |
| **Saved / My schedule** | «♥» — додавання активності в особисту програму без бронювання місця. |
| **MediaLink** | картка-посилання на зовнішню фотогалерею з обов'язковою обкладинкою. |
| **WinStyle** | внутрішній мерч-стор: резерв + QR на видачу, без оплати в v1. |
| **EventStyle** | правила, дрес-код, чек-ліст речей. |
| **Secret** | зашифроване в БД значення інтеграційного ключа. |
