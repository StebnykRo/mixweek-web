## 2. Обов'язкові тестові набори

### 2.1 Тенант-ізоляція (`tests/e2e/tenant-isolation.spec.ts`)
Параметризований тест по **канонічному переліку сутностей з
`docs/02` §4.1** (список імпортується з коду, не дублюється в тесті).
Для кожної: користувач тенанта B звертається за прямим `id` обʼєкта
тенанта A через GET / PATCH / DELETE / вкладені маршрути / Server Action /
експорт → **404 у всіх випадках**. Плюс прямий тест RLS на рівні БД
(запит під `app_user` з чужим `app.tenant_id` повертає 0 рядків).

### 2.2 Автентифікація (`tests/e2e/auth.spec.ts`)
Повний перелік — `docs/03-auth.md` §11.

### 2.3 Конкурентність (`tests/integration/concurrency.spec.ts`)
- 50 паралельних реєстрацій на 10 місць.
- 20 паралельних резервів останнього товару.
- Подвійний сабміт з тим самим `Idempotency-Key` → один результат.
- Промоушен з waitlist при паралельних скасуваннях не дублює місця.

### 2.4 Час і таймзони (`tests/unit/time.spec.ts`)
Фази івенту, «Зараз/Далі», нагадування, тихі години — для
`Asia/Nicosia`, `Europe/Kyiv`, `America/New_York`, включно з переходом на
літній час і межами доби.

### 2.5 Брендинг (`tests/e2e/branding.spec.ts`)
- Вхід з `@softswiss.com` → бренд A; з `@acme.example` → бренд B.
- Токени застосовуються в SSR (немає FOUC — перевірка першого кадру).
- Бренд з непрохідним контрастом не публікується.
- Спроба інʼєкції CSS через токени відкидається валідатором.
- Скріншот-тести обох брендів на 10 екранах.

### 2.6 Безпека (`tests/e2e/security.spec.ts`)
- Усі заголовки з `docs/12` §3 присутні на кожній відповіді.
- CSP без `unsafe-inline`/`unsafe-eval`.
- Персональні відповіді мають `private, no-store` + `Vary: Cookie`.
- POST без валідного `Origin` → 403.
- Анонімний запит до кожного захищеного маршруту → 401/404 (автоперебір
  маршрутів з маніфесту).
- Server Actions недоступні без автентифікації.
- Open redirect у `?next=` неможливий.
- Завантаження SVG як обкладинки → відхилено; EXIF видалено.

### 2.7 Офлайн (`tests/e2e/offline.spec.ts`)
- Програма, мапа, help доступні при `context.setOffline(true)`.
- Банер офлайну зʼявляється.
- ♥ офлайн ставиться в чергу і синхронізується після відновлення.
- У Cache Storage немає жодної відповіді з `Cache-Control: no-store`;
  персональні дані лежать лише в IndexedDB і лише з
  `SW_PERSONAL_ALLOWLIST` (`docs/13` §4).
- Вихід з акаунта очищає Cache Storage та IndexedDB.
- Офлайн-код чек-іну відображається, короткоживучий токен — ні.

## 3. Критерії приймання v1

### A. Автентифікація і доступ
- [ ] Вхід за корпоративною поштою працює з першого разу на мобільному
      без перемикання застосунків (код у полі, автопідстановка).
- [ ] Другий фактор налаштовується й вимагається згідно з політикою.
- [ ] Користувач бачить свої активні сесії й може їх завершити.
- [ ] Невідомий домен не отримує доступу і не дізнається, чи існує акаунт.
- [ ] Гість за інвайтом бачить рівно один івент.

### B. White-label
- [ ] Два тенанти на одному інстансі мають різні лого, кольори, назву й
      шрифти; ніде немає перехресних витоків.
- [ ] Бренд застосовується одразу після введення email, до входу.
- [ ] Зміна теми в адмінці зʼявляється у користувачів без деплою
      (≤ 5 хв, час кешу) і відкочується в один клік.
- [ ] Івент може мати власну тему, що перекриває тему тенанта.

### C. Івенти й реєстрація
- [ ] Вкладки Майбутні / Минулі / Мої працюють, сортування коректне.
- [ ] Реєстрація з формою, capacity й waitlist працює без овербукінгу.
- [ ] Скасування підвищує наступного з черги й повідомляє його.
- [ ] Минулий івент відкривається read-only з блоком фото.
- [ ] `.ics`-експорт імпортується в Google і Apple Calendar.

### D. Програма
- [ ] Фільтри за **днем, часом доби, категорією і локацією** комбінуються
      логікою AND, зберігаються в URL і відновлюються при поверненні.
- [ ] Фільтр часу працює в таймзоні івенту, а не браузера.
- [ ] ♥ працює оптимістично й переживає перезавантаження.
- [ ] «Зараз/Далі» правильні в таймзоні івенту, оновлюються щохвилини.
- [ ] Перенесення активності повідомляє тільки зацікавлених.

### E. Мапа, контент, мерч
- [ ] Мапа з пінами працює офлайн, піни доступні з клавіатури.
- [ ] EventStyle-чекліст зберігає стан між пристроями.
- [ ] Help доступний офлайн.
- [ ] Резерв мерчу не перевищує залишок; QR видачі короткоживучий.

### F. Медіа
- [ ] Картку не можна опублікувати без обкладинки.
- [ ] Посилання відкривається з попередженням про зовнішній сайт.
- [ ] Публікація медіа розсилає сповіщення учасникам івенту.
- [ ] Обкладинки не містять EXIF/GPS.

### G. Нотифікації
- [ ] Пуш працює на Android Chrome і на iOS у встановленій PWA.
- [ ] Тим, у кого пуш недоступний, критичні повідомлення йдуть email-ом.
- [ ] 3 000 доставок розмазуються jitter-ом і не кладуть застосунок.
- [ ] Налаштування типів працюють, критичні не вимикаються.

### H. Адмінка
- [ ] Організатор без розробника може: створити івент, наповнити програму,
      завантажити мапу, налаштувати бренд, розіслати сповіщення, додати
      фото-лінки, вивантажити реєстрації.
- [ ] Матриця прав дотримана; чутливі дії потребують step-up.
- [ ] Кожна мутація видима в аудит-лозі.
- [ ] Секрети встановлюються й ротуються, значення не читається назад.

### I. Якість
- [ ] Бюджети продуктивності з `docs/13` §1 витримані.
- [ ] axe: 0 порушень serious/critical.
- [ ] Усі 4 навантажувальні сценарії проходять.
- [ ] Чекліст релізу з `docs/12` §15 повністю закритий.

## 4. Ручне тестування перед релізом

Обовʼязково на **реальних пристроях**: iPhone (Safari, PWA з екрана
«Додому»), Android (Chrome), ноутбук (Chrome + Safari).

Сценарій «день учасника» повністю, з увімкненим дроселюванням мережі
(Slow 4G) і з вимкненою мережею на частині шляху:
вхід → онбординг → перегляд Home → реєстрація на івент → фільтр програми →
♥ трьох активностей → бронювання воркшопу з лімітом → перегляд мапи →
резерв мерчу → EventStyle-чекліст → отримання пуша про зміну → перегляд
минулого івенту й фото → зміна мови → вихід.

Сценарій «день організатора»: створення івенту з нуля до публікації за
≤ 30 хвилин, розсилка, чек-ін сканером, експорт.

## 5. Definition of Done для будь-якої задачі

1. Код відповідає правилам `CLAUDE.md`.
2. Є unit-тести на логіку і e2e на потік (включно з негативним і
   крос-тенантним випадком).
3. Пройдено чекліст безпеки PR (`docs/12` §14).
4. Перевірено на 390 px і 1440 px, у двох брендах.
5. Стани loading / empty / error / offline реалізовані.
6. Локалізовано (en обовʼязково, ru/uk — ключі додані).
7. A11y: клавіатура, фокус, контраст, aria.
8. Оновлено відповідний `docs/*.md`.
9. Немає нових попереджень лінту й типів.
10. Бюджет бандла не перевищено.
