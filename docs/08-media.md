# 08 · Фото та медіа після івенту

## 1. Рішення й межі

Платформа **не зберігає фотографії учасників**. Вона зберігає **картки-
посилання** на зовнішні галереї. Кожна картка **обов'язково** має власну
обкладинку («аватарку»), яка завантажується в наше сховище.

Чому так:
- нуль ризиків GDPR-зберігання зображень людей і питань з правами
  фотографів;
- нуль інфраструктури під терабайти;
- організатори й так уже користуються Google Drive / Pixieset / Dropbox;
- обкладинка вирішує єдину проблему цього підходу — «стіна однакових
  синіх посилань».

Схема під власне сховище закладена (`media.self_hosted_upload`), але в v1
вимкнена й не реалізується.

## 2. Типи карток (`MediaKind`)

| Kind | Призначення | Типовий провайдер |
|---|---|---|
| `PARTICIPANT_UPLOAD` | спільна папка, куди учасники **заливають** свої фото | Google Drive, Dropbox |
| `PHOTOGRAPHER_GALLERY` | галерея професійних фотографів (перегляд/скачування) | Pixieset, SmugMug, Flickr, Drive |
| `AFTERMOVIE` | відеоролик | YouTube, Vimeo |
| `VIDEO` | інші відео | YouTube, Vimeo |
| `PRESS` | публікації, пресреліз | будь-який |
| `MATERIALS` | презентації, записи воркшопів | Drive, OneDrive |

Картки з `acceptsUploads = true` отримують явний бейдж
**«Можна завантажувати»** і пояснення в описі.

## 3. Обкладинка — обов'язкове поле

Правила:
- Формати на вході: JPEG, PNG, WebP, AVIF. **SVG заборонено** (вектор
  атаки XSS).
- Максимум 10 МБ, мінімум 800×450, співвідношення нормалізується до 16:9
  (кроп по центру з можливістю ручного позиціонування).
- Обробка при завантаженні (`sharp`, у воркері):
  повторне кодування (обов'язково — знищує вбудований активний вміст),
  видалення **всіх** EXIF (включно з GPS), генерація трьох розмірів
  (1600 / 800 / 400 px, WebP + AVIF) + blurhash-плейсхолдер.
- Зберігання: `s3://{bucket}/public/{tenantId}/media/{mediaLinkId}/{size}.webp`,
  віддача через CDN з `Cache-Control: public, max-age=31536000, immutable`.
- Ім'я файлу генерується сервером (cuid2), оригінальне ім'я не
  використовується в шляху.

Якщо обкладинки немає — картку **не можна опублікувати** (валідація на
рівні API, не тільки UI).

**Помічники в адмінці:**
- «Взяти кадр з відео» для YouTube/Vimeo (через oEmbed thumbnail, з
  обов'язковим повторним кодуванням у нас);
- «Використати фото з програми» — вибір з уже завантажених зображень івенту;
- «Згенерувати обкладинку» — брендований градієнт з палітри + назва
  (fallback, коли фото немає).

## 4. Безпека зовнішніх посилань (критично)

1. Тільки схема `https:`. `http`, `javascript:`, `data:`, `file:` —
   відхиляються валідатором.
2. **Allowlist доменів** (налаштовується `SUPER_ADMIN`, дефолт):
   `drive.google.com`, `photos.google.com`, `docs.google.com`,
   `dropbox.com`, `1drv.ms`, `onedrive.live.com`, `flickr.com`,
   `smugmug.com`, `pixieset.com`, `youtube.com`, `youtu.be`, `vimeo.com`.
   Домен поза списком → потрібне явне підтвердження `TENANT_ADMIN`
   зі step-up 2FA, запис в `AuditLog`.
3. Ніякого серверного фетчу довільного URL. Якщо колись знадобиться
   (oEmbed) — тільки через SSRF-safe клієнт: резолв DNS заздалегідь,
   заборона приватних діапазонів (`10/8`, `172.16/12`, `192.168/16`,
   `127/8`, `169.254/16`, `::1`, `fc00::/7`), заборона редиректів на
   приватні адреси, таймаут 5 с, ліміт відповіді 1 МБ.
4. Рендер: `target="_blank"` + `rel="noopener noreferrer nofollow"` +
   `referrerpolicy="no-referrer"`.
5. Перед переходом — короткий інтерстишал (bottom sheet):
   «Ви переходите на **pixieset.com** — сайт партнера. Посилання додав
   Іван П., 12.11.2026.» з кнопками «Відкрити» / «Скасувати». Показується
   один раз на домен на сесію.
6. Жодних `<iframe>` зі сторонніх доменів у v1 (навіть YouTube) —
   тільки перехід за посиланням або `youtube-nocookie` за окремим
   фіче-флагом `media.embed`.

## 5. Екран `/events/[slug]/media`

**Мобільний:** заголовок «Фото та матеріали», підзаголовок з назвою
івенту. Групи по `kind` у фіксованому порядку:
*Ваші фото* (PARTICIPANT_UPLOAD) → *Фотографи* → *Відео* → *Матеріали* →
*Преса*. Одна колонка карток.

**Картка (`MediaLinkCard`):**
```
┌──────────────────────────────┐
│  обкладинка 16:9 (blurhash)  │
│  ┌───────────────┐           │
│  │ бейдж kind    │           │
│  └───────────────┘           │
├──────────────────────────────┤
│ Назва                        │
│ Автор · ~450 фото            │
│ Опис (2 рядки)               │
│ 🔒 Потрібен корп. акаунт     │  ← accessNote
│ [ Відкрити ↗ ]  [ Копіювати ]│
└──────────────────────────────┘
```

**Десктоп:** сітка 2–3 колонки, ліворуч фільтр по типу.

**Стани:** якщо медіа ще немає — «Фото зʼявляться незабаром. Ми надішлемо
сповіщення, коли галереї будуть готові» + тумблер «Повідомити мене».

**Точки входу:** таб/пункт навігації · блок на Home минулого івенту ·
картка в списку минулих івентів (бейдж «Фото») · пуш «Фото з івенту готові».

## 6. Робочий процес організатора

1. Після івенту створює картку `PARTICIPANT_UPLOAD` з посиланням на
   спільну папку **з правами на завантаження**, ставить `acceptsUploads`.
2. Отримує галерею від фотографів → створює `PHOTOGRAPHER_GALLERY` з
   іменем автора й посиланням.
3. Завантажує обкладинки, впорядковує drag-and-drop.
4. Публікує (`status = PUBLISHED`) → одна кнопка «Повідомити учасників»
   створює `Notification(MEDIA_READY)` для тих, хто був на івенті
   (`ATTENDED`/`CONFIRMED`).

Адмінка попереджає, якщо посилання на Google Drive має обмежені права
(перевірка робиться підказкою в UI, не фетчем).

## 7. Приватність

- У картці **обов'язковий** текст-нагадування для `PARTICIPANT_UPLOAD`:
  «Завантажуючи фото, переконайтеся, що люди на них не проти публікації».
- Згода `PHOTO_USAGE` збирається під час реєстрації на івент
  (`ConsentKind.PHOTO_USAGE`) — окремим чекбоксом, не в складі Terms.
- Кнопка «Поскаржитися» на картці галереї → `POST /media/{id}/reports`
  (модель `MediaReport`, `docs/02`) з причиною (приватність / недоречний
  вміст / зламане посилання / немає доступу) і коментарем. Скарга падає в
  чергу адмінки (`docs/10` §3.12b); організатор вирішує питання на боці
  зовнішньої галереї. Ми не модеруємо чужий контент, але даємо канал і
  фіксуємо реакцію.
- Обкладинки — єдині зображення в нашому сховищі; їх видалення миттєве.

## 8. Тести

1. Публікація без обкладинки → 422.
2. SVG як обкладинка → відхилено.
3. Зображення з GPS-EXIF → після обробки метаданих немає (перевірка
   `exiftool` у тесті).
4. URL з доменом поза allowlist → потребує підвищених прав.
5. `javascript:` / `http:` URL → відхилено на рівні Zod.
6. Картка тенанта A недоступна за прямим id користувачу тенанта B → 404.
7. Інтерстишал показується один раз на домен на сесію.
8. Публікація медіа шле нотифікацію лише учасникам цього івенту.
